## A. ローカルモックテスト

### 仕組み
- `test/helpers/gas-mock.js`：SpreadsheetApp / PropertiesService / UrlFetchApp / LockService / Utilities / Session をインメモリで再現
- `test/helpers/load-gas.js`：`src/*.js` を GAS と同じく「全ファイルが1つのグローバル空間を共有する」形で読み込む
- `test/helpers/fixtures.js`：Claude / WordPress の応答のダミー（実キーではない固定文字列を使用）
- UrlFetchApp はモック未設定だと例外になるため、**誤って外部に通信することはありません**
- 時計を差し替えて、実時間を待たずに「6分制限」「10分停止判定」を再現

### 実行手順
```bash
# Node.js 20 以上（外部パッケージのインストールは不要）
npm test            # 結果のみ
npm run test:report # テスト名つきで表示
```

5本とも勤怠管理に関係するため、まとめでキンタイ Cloud が紹介されるのは想定どおりです（記事全体で2回以内）。

**手順**
1. 修正版を GAS に反映（`npm run gas:check` → `npx clasp push`）し、「設定状況を確認」で「プロンプト：v2」と表示されることを確認
2. 記事管理シートに4本の行がなければ、手で追加するか「初期設定 > テスト用キーワードを追加」を実行（既にあるキーワードは追加されないため、「勤怠管理 エクセル 限界」の既存2行はそのまま）。4本のステータスが「未生成」であることを確認
3. まず G-1 だけ「選択行の記事を生成」し、処理結果・文字数・費用を確認（1本 約 $0.003、約30秒）
4. 問題がなければ「未生成の記事をまとめて生成」で残り3本を生成（約1.5〜2分。6分の上限内）
5. 各記事で次を記録する

| 記録項目 | 見る場所 | 合格の目安 |
|---|---|---|
| 処理結果 | 記事管理の「処理結果」 | 「OK：…（試行1回・プロンプトv2）」。「要確認」の場合は内容を記録 |
| 文字数・説明文 | 記事管理の「文字数」、`=LEN(説明文のセル)` | 2,000〜3,000字、120字以内 |
| サービス名 | 記事本文の Markdown 列を「キンタイ」で検索 | 0〜2回。まとめで選択肢の1つとして紹介。機能・料金・実績の記述がない |
| 箇条書き | 記事本文の HTML 列で `<li>` を検索 | `<ul>` / `<ol>` の中にあり、`<p>` の中に「- 」が残っていない |
| 断定表現・法令 | 本文を目視（処理結果の「要確認」も参考） | 効果・費用を言い切っていない。法令の数値・期限・罰則を断定せず、公的情報・専門家への確認を促している |
| 費用・時間 | 記事本文の「推定費用」、処理開始〜最終更新 | 1本 $0.005 未満、1分未満 |
