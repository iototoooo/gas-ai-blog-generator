# プロンプト改善（v1 → v2）

## 背景
実環境の最初の生成（Haiku 5.5、本文2,211文字、説明文80文字、API 1回、約$0.0028、約27秒）は、文章が自然で構成も適切でした。
一方で、次の3点に改善の余地がありました。

- 具体性：一般論が多く、実際の業務場面が見えにくい
- 判断材料：読者が自分で実行できる方法や、判断の基準が少ない
- 導線：サービス（キンタイ Cloud）への自然な案内がない

## v1 の分析

| 観点 | v1 の指示 | 起きやすいこと |
|---|---|---|
| 検索意図 | 「検索意図に正面から答える」の1文だけ | 見出しが「〜とは」「〜の重要性」のような抽象的なものになる |
| 具体性 | 指示なし | 「〜が大切です」「〜を意識しましょう」で終わる一般論 |
| 実行可能性 | まとめで「次の行動を示す」のみ | 手順や確認方法がない |
| 数値 | 「出典のない数値は書かない」 | 数値を避けすぎて規模感が伝わらない（仮の計算例の扱いが決まっていない） |
| サービス導線 | なし | 紹介がない。もし書かせると、機能や料金を作ってしまうおそれがある |
| 法令・制度 | 医療・法律・金融で断定を避ける（一般的な指示） | 労働時間や割増率などの数値を断定してしまうおそれがある |

## v2 で変えたこと

| 改善点 | v2 の指示 |
|---|---|
| 検索意図に答える見出し | 書く前に「読者は誰か・いちばん知りたい問い・関連する問い」を考えさせる。H2は ①問いへの直接の答え ②改善の手順 ③つまずきやすい点・判断の考え方 の順にし、抽象的な見出しを禁止。導入の最初の3文以内で結論を示す |
| 具体的な業務場面 | 各H2に「誰が・いつ・どの作業で・何に困るか」を含む場面を最低1つ入れる。ただし実在の企業の事例や体験談としては書かない |
| 実行できる改善方法 | 2つ目のH2に、3〜5個の手順を箇条書きで入れる。各手順に「確認方法」を付け、費用がかからない方法から並べる |
| 仮の計算例 | 必要なときだけ1つまで。直前に「※以下は説明のための仮の数値です。実際の数値は職場によって異なります。」と書き、前提と計算式を示す |
| サービス導線 | キーワードと関連があるときだけ、まとめで1回、読者の選択肢の1つとして紹介する（記事全体で最大2回）。売り込み表現・他社比較・「ツールで全部解決」は禁止。記事の大部分はツールなしで実行できる内容にする |
| 製品情報を作らない | 機能・料金・実績・効果は `SERVICE_FACTS`（Script Properties）に書かれた内容だけを使う。未設定なら、サービス名とカテゴリ以外は書かない |
| 法令・制度 | 条文番号・数値・期限を断定せず、一般的な考え方にとどめる。厚生労働省の情報や社会保険労務士などの専門家への確認を促し、制度が改正されうることを示す |

変えていないこと：2,000〜3,000文字、導入＋H2見出し3つ＋まとめ、説明文120文字以内、出力形式（JSON Schema）、サンプル記事の扱い、書き直しの条件。

## 生成後の自動チェック（追加）

以下はプログラムで機械的に判定できる範囲のチェックです。見つかった場合は「注意」として処理結果に表示し、**書き直し（再課金）はしません**。

| チェック | 条件 |
|---|---|
| 宣伝過多 | サービス名が3回以上出てくる（空白や全角・半角の違いは無視して数える） |
| 誇大・断定表現 | 「絶対」「100%」「No.1」「業界最安・業界初」「日本一」「確実に」 |
| 仮の数値の注記漏れ | 仮定した人数・日数・金額などを使った計算例の近く（同じ導入・H2・まとめの中で、直前6文以内か直後の文）に「仮の数値」などの注記がない。法令の数値・条文番号・日付・時刻は対象外。仮か実際の数値か判断できない例も「注意」にする（2026-11-18 改善。[詳細](09-legal-accuracy.md#4-仮の数値の警告g-3は誤検知か)） |

「具体的か」「法令の記述が正しいか」は機械では判定できないため、人がチェックリスト（下記）で確認します。

## 費用への影響
システムプロンプトが約800文字から約2,300文字に増えます。事前の見込みは入力 +約1,000トークンでしたが、実測では +1,509トークンでした（下記）。それでも Haiku 5.5 では1記事あたり約 +$0.0005 です。

## 実測比較（2026-11-17、キーワード「勤怠管理 エクセル 限界」、Haiku 5.5）

| 項目 | v1（改善前） | v2（改善後） | 差 |
|---|---|---|---|
| 本文の文字数 | 2,211 | 2,110 | −101（どちらも 2,000〜3,000 の範囲内） |
| メタディスクリプション | 80文字 | 71文字 | −9（どちらも120以内。目安の90〜110文字より短い） |
| 生成時間 | 約27秒 | 約28秒 | +約1秒 |
| 入力トークン | 2,095 | 3,604 | +1,509（+72%） |
| 出力トークン | 5,168 | 5,860 | +692（+13%） |
| API呼び出し | 1回 | 1回 | 書き直しなし |
| 推定費用 | $0.002794 | $0.003290 | +$0.000496（+18%） |

- 記事の形式（文字数・見出し3つ・説明文120文字以内）は、どちらも書き直しなしで満たした
- 費用の増加は1記事あたり約0.05セントで、100記事でも約 $0.05 の差。生成時間もほぼ同じ
- **今後の既定は v2 とする**（`PROMPT_VERSION` は未設定のまま）

### v2 記事で見つかった課題と対応（2026-11-18）

| 課題 | 原因 | 対応 |
|---|---|---|
| 「費用や体制の変更は要らず、効果は翌月の締め作業で確認できます」のような断定 | v2 の「費用や大きな体制変更が要らない方法から順に示す」という指示が、言い切りを誘っていた。効果・費用の断定を禁じる指示もなかった | 指示を「手軽に始めやすい方法から（費用不要・体制変更不要と断定しない）」に変更。「効果・費用・手間・期間は断定しない」を追加し、避ける例と書き方の例を示した。生成後の自動チェックにも「効果・費用の断定」を追加（要確認として表示） |
| 箇条書きが WordPress 用の HTML でリストにならない場合がある | HTML 変換が「空行で区切られ、すべての行が `- ` で始まるまとまり」しかリストとして扱っていなかった。「手順は次のとおりです。」の直後に空行なしで続く箇条書きや、`1. ` で始まる番号付きの手順は、`<p>` の中に `- …<br>` が残っていた | 行ごとに判定し、段落・`<ul>`・`<ol>` に分けるよう修正。プロンプトにも「箇条書きの前後は空行」「手順は `1. ` 形式」を追加 |

> v1 の文言は変えていません（比較用。テストで初期版との完全一致を確認）。
> 生成済みの記事本文（HTML列）は自動では作り直されません。修正前に生成した記事を WordPress に保存する場合は、下書き画面でリストの表示を確認してください。

## 改善前後の比較手順（実環境）

既存の記事（生成済みの行）は変更しません。**同じキーワードで新しい行を2つ追加**して比べます。

1. 記事管理シートの最終行の下に、同じキーワード・サブキーワードで2行追加する（IDは生成時に自動採番）
2. Script Properties に `PROMPT_VERSION=v1` を登録 → 1行目を「選択行の記事を生成」
3. `PROMPT_VERSION` を削除（＝v2）→ 2行目を生成
4. 処理結果の「プロンプトv1／v2」の表示と、実行ログで版を確認する
5. 下のチェックリストで比較し、結果を `docs/04-testing.md` の B-23 に記録する

> 生成済みの行を「再生成（上書き）」すると、最初の記事が消えます。比較では使わないでください。
> 送るプロンプトは、API を呼ばずに `npm run prompt:preview -- "<キーワード>" "<サブキーワード>" --version=v1` で確認できます。

### 比較チェックリスト

| # | 観点 | 確認内容 |
|---|---|---|
| 1 | 検索意図 | 見出しだけ読んで、検索した問いへの答えがわかるか |
| 2 | 結論の早さ | 導入の最初の3文以内に結論があるか |
| 3 | 業務場面 | 各H2に、誰が・いつ・どの作業で困るかが具体的に書かれているか |
| 4 | 実行可能性 | 今日から試せる手順と確認方法があるか |
| 5 | 仮の数値 | 計算例がある場合、仮の数値である注記と前提が書かれているか |
| 6 | 導線 | サービス紹介が関連のあるときだけで、まとめで自然に1回程度か。売り込みに感じないか |
| 7 | 事実性 | 書かれた機能・料金・実績がないか（`SERVICE_FACTS` 未設定の場合）。存在しない事例・統計がないか |
| 8 | 法令 | 検索意図に必要な法令の数値が抜けていないか。書かれている数値・期限・罰則が公的資料と一致するか（記憶で書かれていないか）。公的情報・専門家への確認を促しているか（[09](09-legal-accuracy.md)） |
| 9 | 仕様 | 文字数・見出し3つ・説明文120文字以内を満たすか（処理結果が「OK」か） |
| 10 | コスト | 入力・出力トークンと推定費用の差 |

## 今後の検討
- `SERVICE_FACTS` には、キンタイ Cloud の公式資料で確認できた機能だけを書く（推測で書かない）
- サービスページのURLへのリンクは、WordPress 側で人が追加する運用とする（自動でリンクは挿入しない）
- v2 で品質が足りない場合は、`CLAUDE_MODEL=claude-sonnet-5-5` との比較（B-21）も行う
