## 2. 有給休暇記事（G-1）を作り直すときの確認手順

既存の記事は残すことにしています。そのため「選択行を再生成（上書き）」は使わず、**新しい行で生成します**。再生成（上書き）を使うと、タイトルと本文が上書きされます。

**生成の前**
1. G-1 の行のステータスが「要確認」になっていることを確認します。これで、誤って下書き保存されることはありません。
2. 記事管理シートの最終行の下に、新しい行を追加します。
   - キーワードに「有給休暇 管理 方法」、サブキーワードに「5日義務, 取得率」と入力します。
   - ステータスは「未生成」にします。ID は空欄のままで、生成時に自動で付きます。
   - 「テスト用キーワードを追加」は使えません。同じキーワードが既にあると追加されないためです。
3. 「設定状況を確認」で、プロンプトが v2 になっていることを確認します。

**生成**
4. 新しい行を選択して「選択行の記事を生成」を実行します。費用の目安は1回で約 $0.003〜0.004、書き直しが起きると約 $0.007 です。

**生成の後**
5. 処理結果を確認します。
   - 「OK」または「注意」であれば、文字数などの仕様は満たしています。
   - 「要確認」であれば、また文字数が足りていません。もう一度生成する前に原因を記録してください（何回生成するかは費用と相談して決めます）。
6. 次の「3. 法令の確認」の G-1 の項目を、記事本文と照らし合わせます。
7. 下書き保存してよいのは、法令の確認が済んだ記事の行だけです。旧記事（G-1）の行は「要確認」のまま比較用として残します。

## 3. 法令の確認（記事ごとの観点）

### G-1 有給休暇管理
- 年5日の取得義務の対象者（年10日以上の有給休暇が付与される労働者）を、「全従業員」と書いていないか。
- 期限を「付与日（基準日）から1年以内」と正しく扱っているか。「毎年4月〜3月」などと決めつけていないか。
- **時間単位で取った有給休暇を、年5日の義務の日数に含めていないか。** 最も誤りやすい点です。半日単位で取った分は数えられます。
- 取得率の計算式を「公式の定義」として示していないか。示すなら、どの調査の定義なのかを書く。
- 年次有給休暇管理簿を作る義務と、罰則について、金額や年数を推測で書いていないか。

### G-3 36協定
- 原則の上限（月・年）、特別条項を使う場合の上限（年・単月・複数月平均）、月45時間を超えてよい回数は、検索している人が最も知りたい情報です。**省略されていないか。書かれている場合は数値が正しいか。**
- 「時間外労働」だけの上限と、「時間外労働と休日労働の合計」の上限を混同していないか。
- 罰則の内容が最新か。刑法の改正により、懲役は拘禁刑に変わっています。
- 適用が猶予されていた業種（建設・運転・医師など）の扱いを断定していないか。

## 4. 「仮の数値」の警告（G-3）は誤検知か

**誤検知の可能性が高いと判断しています。ただし記事本文を見ていないので、確定はできません。** 判定は 4-1 のとおり改善しました（P1。2026-11-18）。

改善前の判定の仕組みは次のとおりです。
- 1つの文に「たとえば」「例えば」「仮に」「試算」などの言葉があり、かつ「時間・日・回・円」などの単位が付いた数字がある。
- そして、記事のどこにも「仮の数値」の注記がない。

この2つがそろうと警告します。36協定の記事は、法定の時間・回数・日付が多く出てくる典型的な記事なので、次のような**創作ではない数値にも反応してしまいます**。

| 文の例 | 判定 | 誤検知か |
|---|---|---|
| たとえば、原則の上限は月45時間・年360時間とされています。 | 警告する | 誤検知（法令の数値） |
| たとえば1日8時間・週40時間を超える労働が時間外労働にあたります。 | 警告する | 誤検知（法令の数値） |
| 例えば、特別条項を使えるのは年6回までとされています。 | 警告する | 誤検知（法令の回数） |
| たとえば毎月25日に締めて、翌月10日に支払う職場では… | 警告する | 誤検知（日付） |
| 例えば、9時から18時までの勤務で休憩を1時間とる場合です。 | 警告する | 誤検知に近い（時刻） |
| たとえば、ある月の残業が50時間だった場合、特別条項が必要か確認します。 | 警告する | **正しい警告**（仮の数値） |
| 原則の上限は月45時間・年360時間とされています。 | 警告しない | —（「たとえば」がない） |

これらの判定は、改善前の `hasUnlabeledEstimate_` に上の文を入力して確かめたものです。

**見分け方**：G-3 の記事本文の中で、「たとえば」「例えば」「仮に」と、単位の付いた数字が同じ文にある箇所を探してください。
- その数字が法令の数値や日付であれば誤検知です。
- 職場を想定した数字であれば、正しい警告です（注記を追記してください）。

**判定ロジックの限界**
- 単位が付いているかどうかしか見ていないため、法令の数値・日付・時刻と、創作した数値を区別できません。
- 注記の有無は記事全体で1つでも見つかればよい、という判定です。注記が1か所あると、ほかの段落に注記のない試算があっても警告しません（こちらは見逃しの方向の誤りです）。

### 4-1. 改善後の判定（P1）
1文ずつ、次の順に判定します（`ArticleFormatter.js` の `classifyEstimateSentence_` と `findEstimateIssues_`）。

1. 日付（毎月25日、11月18日、25日締め）、時刻（9時から、8:30）、条文番号（第36条）、年（2026年）を取り除きます。そのうえで、単位の付いた数値（人・時間・日・円・%・回など）が残らなければ対象外にします。
2. 仮定がはっきりしている表現があれば「**計算例**」と判定します。法令の文脈であっても同じです。
   - 対象の表現：仮に、試算、計算すると、としたら、とすると、ある月、従業員30人、50人規模の会社、30人×2時間、＝60時間 など
3. 「〜の場合、…は50%になります」のように、条件から結果の数値を導く文は「計算例」と判定します。ただし法令の文脈の文は「**判断できない**」とします。
4. 例示の言葉（たとえば、例えば、場合）だけの文は、次のように判定します。
   - 法令の文脈（上限・義務・罰則・協定・特別条項・とされ・定められ・時間外労働 など）であれば、法令の数値として対象外にします。
   - それ以外は「**判断できない**」とします。
5. 「計算例」「判断できない」の文は、近くに注記があれば問題なしとします。近くとは、同じ導入・H2・まとめの中で、直前の6文以内か直後の1文です。注記がなければ「注意」として、該当する文の数と例を処理結果に表示します。

| 文の例 | 改善前 | 改善後 |
|---|---|---|
| たとえば、原則の上限は月45時間・年360時間とされています。 | 警告 | 対象外 |
| 例えば、特別条項を使えるのは年6回までとされています。 | 警告 | 対象外 |
| たとえば1日8時間・週40時間を超える労働が時間外労働にあたります。 | 警告 | 対象外 |
| たとえば毎月25日に締めて、翌月10日に支払う職場では… | 警告 | 対象外 |
| 例えば、9時から18時までの勤務の場合です。 | 警告 | 対象外 |
| たとえば、ある月の残業が50時間だった場合… | 警告 | 計算例（注記がなければ注意） |
| 例えば取得率が50%の部署では… | 警告 | 判断できない（注意） |
| 導入にだけ注記があり、3つ目のH2に「従業員30人で計算すると…」 | 警告しない（見逃し） | 計算例（注意） |

改善後も、すべての文を正しく分類できるわけではありません。「注意」が出た文は人が読んで判断します。「注意」が出ないことは、内容が正しいことの保証にはなりません。

## 5. 36協定の記事で法定の上限時間が省略される原因

**原因はプロンプト v2 の指示にあります**（AI の誤りではありません）。

- v2 の「事実性・法令」には、「法令や制度（…時間外労働の上限…）は、条文番号・具体的な数値・期限を断定しない」という指示があります。
- この指示は「数値を創作させない」ために入れたものです。しかし実際には「**正しい数値も書かない**」と解釈され、AI は上限時間を書かずに「専門家に確認してください」で済ませました。
- テストの観点（04-testing.md の G-3）も「数値を断定しない」としていたため、確認する側もこの省略を問題として捉えていませんでした。
- 「36協定 残業時間 上限」で検索する人が最も知りたいのは上限の数値です。数値を書かない記事は**検索意図を満たさず、SEO 記事として役に立ちません**。

一方で、AI に数値を自由に書かせると、記憶違いや古い数値（改正前の内容）が混ざる危険があります。

**どちらの方向にも外せない問題**です。そこで、AI に数値を「思い出させる」のではなく、**人が公的資料で確認した数値だけを渡して使わせる**仕組みが必要です（次の節）。

## 6. 法令情報を正確に扱う仕組み（案）

基本の考え方は、**AI に法令・数値・出典を作らせないこと**です。人が確認した情報だけを AI に渡し、記事にはそれ以外の法令の数値を書かせないようにします。

### 6-1. 確認済みの法令情報を渡す（`SERVICE_FACTS` と同じ方式）
- 「法令メモ」シートを新しく作り、テーマごとに人が記入します。今回は案の段階なので、まだ作りません。

| 列 | 例 | 書く人 |
|---|---|---|
| テーマ（キーワードの一部） | 36協定 | 人 |
| 項目 | 原則の上限（月・年） | 人 |
| 内容 | （公的資料に書かれている数値・条件をそのまま） | 人 |
| 出典名 | 厚生労働省のリーフレット・解説ページの名称 | 人 |
| 出典URL | 公的機関のページの URL | 人 |
| 確認日 | 2026-11-xx | 人 |
| 確認者 | 担当者名 | 人 |

- 生成するときは、キーワードに合う行だけを `<legal_facts>` としてプロンプトに入れます。
- プロンプトには次の指示を入れます。
  - 法令の数値・条件は `<legal_facts>` に書かれているものだけを使い、書かれていないものは書かない。
  - 出典は `<legal_facts>` の出典名をそのまま書く。URL や出典を作らない。
  - 例外や業種別の扱いは「対象になるかは確認が必要」と書く。
- 法令メモがないテーマは、いまの v2 と同じく「数値は書かず、公的資料で確認する」ように促します。この場合、検索意図に応えきれないことを処理結果に表示します。

### 6-2. 生成後に自動で照合する
- 本文に出てくる法令の数値を抜き出します。対象は「時間・日・回・か月・万円」などの単位が付き、近くに「上限・義務・罰則・法・協定」などの語がある数値です。
- **法令メモにない数値があれば「注意」にします**。これが創作された数値を検出する仕組みです。
- 出典として書かれた名称が法令メモにない場合や、URL らしい文字列が本文にある場合も「注意」にします。
- 「仮の数値」の判定では、法令メモにある数値と日付・時刻を対象外にします（4節の誤検知を減らすため）。

### 6-3. 古い情報を使わないようにする
- 確認日から一定期間（例：6か月）が過ぎた法令メモは、使わずに「再確認が必要」と表示します。
- 法改正の時期には、法令メモを見直します。改正の情報は、人が厚生労働省の発表で確認します。

## 7. 法令を扱う記事の確認ルール

**ルール**
1. **「生成済み」は公開してよいという意味ではありません。** 文字数・見出し・説明文などの形式を満たしたという意味だけです。
2. **公的資料での確認が済むまで、公開・納品の判断を保留します。** WordPress への下書き保存も、確認が済んでから行います。
3. **確認した資料名・URL・確認日を記録します。** 記録先は、当面は記事管理シートの処理結果の列（先頭に追記）です。確認者の名前も残します。
4. **法令の記述が不正確な場合は、本文を修正するか作り直します。** 作り直した記事も、もう一度確認します。既存の記事を残す場合は、新しい行で作り直します（2節）。
5. **当面、法令を扱う記事のステータスは人が管理します。** システムは法令の正確性を判定しません。

**対象になる記事**：労働時間・残業・休憩・休日・有給休暇・36協定・割増賃金・労働契約・社会保険など、法令や公的制度にふれる記事です。サービスの紹介や一般的な業務改善の記事でも、法令にふれる部分があれば対象にします。

**記録の例**（処理結果の列）

```
法令確認済み 2026-11-20 確認者：（名前）／厚生労働省「（資料名）」（URL）／修正：年5日の義務の対象者の記述を修正
```

### 7-1. 「生成済み」と「公開してよい」は別に判断する

いまの「生成済み」は、**仕様（文字数・見出し・説明文）を満たした**という意味でしかありません。法令の正確性は保証していません。運用で、次のように分けて扱います。

| 段階 | 意味 | 判断する人 |
|---|---|---|
| 生成済み | 仕様を満たした（自動チェック） | システム |
| 法令確認済み | 法令の記述を公的資料で確認した | 人（確認者） |
| 下書き保存済み | WordPress に下書きとして保存した（公開はしていない） | 人 |
| 公開 | WordPress 上で人が公開した | 人（WordPress 側） |

**当面の運用（コードを変えずにできること）**
1. 法令を扱うテーマ（有給休暇・36協定・テレワークの中抜けなど）は、生成されたらステータスを「要確認」に変えておきます。
2. 確認者が 3節の観点で本文を公的資料と照らし合わせます。確認した資料の名称と日付は処理結果の列に追記しておきます（例：「法令確認済み 2026-11-xx ○○資料」）。
3. 確認が済んでから、ステータスを「生成済み」に戻して下書き保存します。
4. 公開は WordPress 上で人が行います。本システムは下書き保存（status=draft）までしか行いません。

**将来の仕組み（修正案 P2）**：記事管理シートに「法令確認」の列（未確認／確認済み／対象外）を追加します。法令を扱うテーマで「確認済み」になっていない記事は、下書き保存できないようにします。
