# 利用マニュアル（初心者向け）

プログラミングの知識がなくても使えるように、画面の操作だけで説明します。

---

## はじめに：全体のイメージ

1. スプレッドシートに「書いてほしい記事のキーワード」を入力する
2. メニューから「記事を生成」を押す → AI（Claude）が記事を書いてシートに保存する
3. 内容を確認する
4. （WordPressを使う場合）メニューから「下書き保存」を押す → WordPress に **下書き** が作られる
5. WordPress の管理画面で最終確認し、**人の手で** 公開する

> このシステムが記事を勝手に公開することはありません。公開は必ずあなたが行います。

---

## 1. 初回の準備（最初の1回だけ）

### 1-1. スプレッドシートとコードの準備
1. Googleドライブで新しいスプレッドシートを作成（名前は自由。例：「ブログ記事生成」）
2. メニュー「拡張機能 > Apps Script」を開く
3. 最初からある `コード.gs` の中身を削除
4. `src` フォルダ内の各ファイルを、同じ名前のスクリプトファイルとして追加し、中身を貼り付け
   （左の「＋」→「スクリプト」。拡張子 `.js` は付けなくてOK）
5. ⚙️「プロジェクトの設定」→「"appsscript.json" マニフェスト ファイルをエディタで表示する」にチェック →
   エディタに出てきた `appsscript.json` を `src/appsscript.json` の内容で置き換え
6. 💾 保存

### 1-2. APIキーの登録
[APIキー設定手順書](01-api-key-setup.md) に沿って、`CLAUDE_API_KEY` を登録します。
WordPress を使う場合は `WP_BASE_URL` / `WP_USERNAME` / `WP_APP_PASSWORD` も登録します。

### 1-3. シートの作成
1. スプレッドシートのタブに戻り、ページを **再読み込み**
2. 数秒後、上部メニューに「記事生成」が表示されます
3. 「記事生成 > 初期設定 > シートを初期化」をクリック
4. 初回は「承認が必要です」と表示されます →「続行」→ 自分のGoogleアカウントを選択
   →「詳細」→「（プロジェクト名）に移動」→「許可」
   （自分で作ったスクリプトなので、この警告が出るのは正常です）
5. もう一度「シートを初期化」を実行すると、4つのシートが作成されます

| シート | 用途 |
|---|---|
| 記事管理 | キーワードを入力し、ステータス・タイトル・説明文・結果を確認する |
| 記事本文 | 生成された本文（Markdown / HTML）を確認する |
| サンプル記事 | 文体の参考にする記事を貼り付ける |
| 実行ログ | いつ・何を実行し・どうなったかの記録 |

### 1-4. サンプル記事の登録（文体を合わせたい場合）
1. 「サンプル記事」シートを開く
2. 3行目に、教材で配布されたサンプル記事のタイトルと本文を貼り付け、「利用する」に `TRUE` と入力
3. 2行目のダミー記事の「利用する」を `FALSE` に変更

> サンプル記事は **語り口の参考** としてのみ使います。AI には「文章を流用しない」ように指示しており、
> さらに25文字以上同じ文章があった場合は、処理結果に「注意：」と表示されます。

## 2. 記事を生成する

### 2-1. キーワードを入力
「記事管理」シートの空いている行に入力します。

| 列 | 入力 | 例 |
|---|---|---|
| キーワード | **必須**。検索されたい言葉 | `有給休暇 管理 方法` |
| サブキーワード | 任意。カンマ区切り | `作業環境, 休憩の取り方` |
| ステータス | `未生成` を選ぶ（空欄でも可） | |

ID・タイトルなどの他の列は自動で入ります。
お試し用に「初期設定 > テスト用キーワードを追加」で5件を自動追加することもできます。

### 2-2. 生成を実行
1. 生成したい行をクリック（複数行を選ぶ場合は最大5行まで）
2. 「記事生成 > 選択行の記事を生成」
3. 1記事あたり1〜2分ほどかかります。ステータスが `生成中` になり、完了すると結果が表示されます

未生成の行をまとめて処理したい場合は「未生成の記事をまとめて生成」を使います（1回最大5件）。
Googleの制限で1回の実行は約6分までのため、時間内に終わらなかった行は「未処理」と表示されます。もう一度実行してください。

### 2-3. 結果の確認
- **記事管理シート**：タイトル、メタディスクリプション、文字数、処理結果
  - 処理結果が `OK：…` なら仕様どおり
  - `注意：…` なら仕様は満たしているが確認したい点がある（サンプルと似ている、誇大・断定表現、仮の数値の注記漏れ、など）
  - `要確認：…`（ステータスも `要確認`）なら、書き直しても文字数・見出し数などの必須条件を満たせなかった記事です。下の「要確認の記事」を参照
- **記事本文シート**：本文全体。行を選んで「選択行の本文を開く」でも移動できます

### 2-4. 要確認の記事
文字数・見出し数・説明文の長さを満たさない記事は、ステータスが `要確認` になります。記事は保存されていますが、このままでは WordPress へ下書き保存できません。

- 少しの不足なら：記事本文を確認し、問題なければステータスを手で `生成済み` に変更してから下書き保存
- 作り直すなら：「選択行を再生成（上書き）」（API料金がかかります）

### 2-5. 法令を扱う記事（有給休暇・36協定・残業・休憩など）
**「生成済み」は、文字数などの形式を満たしたという意味です。公開や納品をしてよいという意味ではありません。** 法令の記述が正しいかどうかは、システムでは確認していません。

1. 生成されたら、ステータスを手で `要確認` に変えます（法令を扱う記事のステータスは、当面は人が管理します）。
2. 記事の中の法令の記述（対象者・上限・期限・罰則・計算式など）を、公的資料（厚生労働省などの最新の資料）と照らし合わせます。
3. 確認した**資料名・URL・確認日**を、処理結果の列の先頭に追記して記録します。
   - 例：「法令確認済み 2026-11-20 厚生労働省『（資料名）』（URL）」
4. 不正確な記述があれば、本文を直すか、新しい行で作り直します。作り直した記事も、もう一度 2〜3 を行います。
5. 確認が済むまでは、WordPress への下書き保存・公開・納品の判断を保留します。確認が済んだら、ステータスを `生成済み` に戻して下書き保存します。

詳しくは「[法令情報の正確性と公開判断](09-legal-accuracy.md)」を参照してください。

### 2-6. 作り直したいとき
行を選んで「選択行を再生成（上書き）」。確認画面で「はい」を押すと作り直します（API料金がかかります）。
WordPress に保存済みの記事は、二重管理を防ぐため再生成できません。

## 3. WordPress に下書き保存する（任意）

1. ステータスが `生成済み` の行を選ぶ
2. 「記事生成 > 選択行をWordPressに下書き保存」
3. 成功すると、ステータスが `下書き保存済み` になり、「WordPress URL」に編集画面のURLが入ります
4. URLを開き、WordPress 上で内容・画像・カテゴリなどを整えてから **自分で公開** します

> WordPress を設定していない場合は「スキップしました」と表示されるだけで、エラーにはなりません。

---

## 4. ステータスの意味

| ステータス | 意味 | できること |
|---|---|---|
| 未生成 | まだ記事がない | 生成 |
| 生成中 | AI が執筆中 | 待つ（10分以上変わらなければ「停止した処理をリセット」） |
| 生成済み | 記事がシートに保存された | 確認・再生成・下書き保存 |
| 要確認 | 記事は保存されたが、文字数などの必須条件を満たしていない | 内容を確認して `生成済み` に変更、または再生成 |
| 投稿中 | WordPress に送信中 | 待つ |
| 下書き保存済み | WordPress に下書きがある | WordPress で確認して公開 |
| 生成エラー | 生成に失敗 | 「処理結果」を読み、もう一度「生成」 |
| 投稿エラー | 下書き保存に失敗 | 「処理結果」を読み、もう一度「下書き保存」 |

---

## 5. やってはいけないこと

- ステータス列を手で `生成済み` などに書き換える（二重投稿防止が働かなくなります）
- 「生成中」の行を、処理中に手で書き換える
- APIキーをシートに書く
- 「記事管理」シートの列の順番を入れ替える・列を挿入する

困ったときは [トラブルシューティング](03-troubleshooting.md) を見てください。
