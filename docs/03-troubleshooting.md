# トラブルシューティング

「処理結果」列やダイアログに表示される `[コード]` から原因を探せます。
詳しい履歴は「実行ログ」シート、または Apps Script エディタの「実行数」で確認できます。

## エラーコード一覧

| コード | 意味 | 主な原因 | 対処 |
|---|---|---|---|
| `CONFIG_MISSING` | 設定不足 | Script Properties 未登録、WP_BASE_URL が http | [APIキー設定手順書](01-api-key-setup.md)で登録。「設定状況を確認」で確認 |
| `AUTH_ERROR` | 認証失敗（401/403） | APIキーの誤り・無効化、WordPressのユーザー名/アプリパスワード誤り、権限不足 | 値を貼り直す（前後の空白に注意）。キーを再発行 |
| `RATE_LIMIT` | レート制限（429） | 短時間に呼びすぎ、利用上限に到達 | 自動で待って再試行済み。それでも出る場合は数分待つ。Console の利用上限・残高を確認 |
| `API_ERROR` | APIエラー | 529（混雑）・5xx（一時障害）・400（リクエスト不正） | 5xx/529 は自動再試行済み。時間をおいて再実行。400 は `CLAUDE_MODEL` 等の設定値を確認 |
| `NETWORK_ERROR` | 通信失敗 | 一時的なネットワーク障害、URLの誤り | 再実行。WP_BASE_URL のつづりを確認 |
| `CALL_LIMIT` | 呼び出し回数の上限 | 1記事あたり4回（書き直し・再試行込み）を使い切った。混雑やレート制限が続いている | 時間をおいて再実行。料金の膨張を防ぐための安全装置です |
| `TIMEOUT` | 時間切れ | GAS の6分制限に近づいた | 選択行を減らして再実行。下記「時間切れ」参照 |
| `REFUSAL` | AIが執筆を控えた | キーワードが安全性の判断に触れた | キーワードの表現を変える。Haiku 5.5 には自動フォールバックがないため、続く場合は `CLAUDE_MODEL=claude-sonnet-5-5` も検討 |
| `TRUNCATED` | 出力が途中で切れた | 出力上限に到達 | 再実行。続く場合は `CLAUDE_MAX_TOKENS` を増やす |
| `INVALID_RESPONSE` | 応答を読めない | 応答形式の乱れ | 再実行 |
| `LOCK_TIMEOUT` | 他の処理が実行中 | 別タブ・別ユーザーが同時に実行 | 少し待ってから再実行 |
| `INVALID_STATE` | 対象外の状態 | 生成済みの行を再度「生成」、未生成の行を「投稿」など | メッセージの指示に従う（再生成メニューなど） |
| `WP_ERROR` | WordPressのエラー | REST API 無効、プラグインによる遮断 | 下記「WordPress」参照 |
| `NOT_FOUND` | 見つからない | シート未作成、本文行の削除 | 「シートを初期化」、または再生成 |

## よくある症状

### メニュー「記事生成」が表示されない
- スプレッドシートを再読み込みしてください（表示まで数秒かかります）
- Apps Script のコードが保存されているか確認
- それでも出ない場合、Apps Script エディタで `onOpen` を選んで ▶実行 → 承認

### 「承認が必要です」「このアプリは Google で確認されていません」
自分で作成したスクリプトでは正常な表示です。「詳細」→「（プロジェクト名）に移動」→「許可」で進めます。

### ステータスが「生成中」「投稿中」のまま変わらない
GAS の時間制限などで処理が途中で止まった可能性があります。
10分以上経過していれば、「記事生成 > 停止した処理をリセット」→「はい」でエラー状態に戻し、再実行できます。
（10分経過していなくても、実行中の処理が無いことが確実なら「いいえ」で全件リセットできます）

### 時間切れ（TIMEOUT）や「未処理」が表示される
- Google の制限で、1回の実行は約6分までです。本システムは4分30秒を過ぎると新しい記事に着手しません
- 一度に選ぶ行を1〜2行に減らしてください
- 1記事の生成自体に時間がかかる場合は `CLAUDE_EFFORT` を `low` にすると速くなります
- UrlFetchApp には応答待ちの上限があるため、長文の生成で通信がタイムアウトすることがあります。
  その場合も `CLAUDE_EFFORT=low` や、より高速なモデル（`CLAUDE_MODEL`）を試してください

### ステータスが「要確認」／処理結果が「要確認：本文がXXXX文字で…」
AI が自動で書き直しても文字数が範囲内に収まらなかった状態です。記事は保存されています（書き直した中で最も条件に近い記事）。
このままでは WordPress へ下書き保存できません。内容を確認して問題なければステータスを `生成済み` に変更し、作り直す場合は「選択行を再生成（上書き）」を実行してください。

> ステータスの選択肢に「要確認」が出ない場合は、「初期設定 > シートを初期化」をもう一度実行してください（既存のデータは変わらず、入力規則だけが更新されます）。

### 処理結果が「注意：サンプル記事と25文字以上一致する箇所があります」
文章の一部がサンプル記事とほぼ同じです。該当箇所を書き換えるか、再生成してください。

### 処理結果が「注意：試算・計算例の近くに『仮の数値』である旨の注記が見当たりません」
「従業員30人で計算すると…」「10日付与で5日取得した場合、取得率は50%になります」のように、仮定した人数・日数・金額などを使った例の近くに注記がない状態です。処理結果には、該当する例の数と最初の文の一部が表示されます。
例の直前に「※以下は説明のための仮の数値です。」と追記してください。

- 注記は**同じ導入・H2・まとめの中で、例の直前（6文以内）か直後の文**に必要です。記事の別の場所に注記があっても、離れた計算例には効きません。
- 法令の数値（「原則の上限は月45時間・年360時間とされています」など）、条文番号、日付（毎月25日締め）、時刻（9時から）、計算式の説明だけの文では表示されません。

### 処理結果が「注意：数値を使った例が、仮の数値か法令などの実際の数値か自動では判断できません」
「例えば取得率が50%の部署では…」のように、例示の言葉と数値はあるものの、仮の数値なのか実際の数値なのかを機械で決められない文です。安全とはみなさずに「注意」として表示しています。
- 仮の数値であれば、例の近くに注記を入れてください。
- 法令や公的な統計の数値であれば、公的資料と一致するかを確認してください。確認の進め方は「[法令情報の正確性と公開判断](09-legal-accuracy.md)」を参照してください。

### 「メタディスクリプションを120文字以内に自動調整しました」
AI の説明文が120文字を超えたため、句点で切り詰めました。不自然なら手で修正してください。

### WordPress：`AUTH_ERROR`（401）
- ログインパスワードではなく **アプリケーションパスワード** を使っているか
- `WP_USERNAME` がユーザー名（メールアドレスではなく）になっているか
- サーバーが `Authorization` ヘッダーを削除している場合があります（一部のレンタルサーバー）。
  `.htaccess` に `SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1` を追加する方法が知られています。サーバー会社の案内を確認してください
- セキュリティ系プラグイン（REST API 制限・ログイン制限）を確認

### WordPress：`WP_ERROR`（404 `rest_no_route`）
- パーマリンク設定が「基本」だと `/wp-json/` が使えないことがあります。「設定 > パーマリンク」で「投稿名」などに変更して保存
- `WP_BASE_URL` に `/wp-admin` などを含めていないか確認（サイトのトップURLのみ）

### WordPress：「既存の下書きを検出し紐付けました」
前回の送信がWordPress側では成功していたのに、応答が届かなかったケースです。二重投稿を防ぐため、既存の下書きを紐付けました。問題ありません。

### WordPress に下書きが2つできてしまった
二重投稿防止は、スラッグ `aiblog-kw-xxx` による検索で行っています。WordPress 上でスラッグを変更した下書きは検出できません。不要な方を削除してください。
また、別のスプレッドシートで同じID（KW-001 など）を使うと既存記事と誤って紐付く可能性があるため、1つのWordPressサイトにつき1つのスプレッドシートで運用してください。

### API の料金が気になる
- Console で利用上限（Spend limit）を設定
- 1記事＝最大2回の呼び出し（書き直し込み）。`MAX_GENERATION_ATTEMPTS=1` で書き直しを無効化できます
- 「生成済み」の行は通常の生成メニューでは処理されないため、誤操作による重複課金は起きません
